# AI Team Office v2 — "회사 건물" 리디자인 (2026-10-21)

v1(DESIGN.md)의 데이터·상태 머신·안전 규칙은 유지. v2 는 **보이는 것**을 바꾼다: 건물·층, 직급·이름, 캐릭터, 픽셀아트, 사용량 그래프.

## 1. 건물과 층 (프로젝트 = 층)
- 화면 왼쪽에 세로 **건물 단면도**(픽셀). 층마다: 층수, 프로젝트 이름(라벨), 지금 일하는 인원 수, 활동 불빛(최근 30초 내 이벤트면 창문이 켜짐), 승인 대기면 빨간 벨.
- 층 번호·이름은 `~/.claude/ai-team-office/building.json` 으로 사용자가 고정할 수 있다. 예:
  `{"floors":{"shop-backend-app":{"floor":1,"label":"쇼핑 백엔드"},"shop-backend-oms":{"floor":2,"label":"쇼핑 OMS"},"web_ui":{"floor":3,"label":"글로벌 UI"},"AI_Team":{"floor":9,"label":"AI 팀 사무실"}}, "ceo":"대표"}`
  파일이 없거나 미등록 프로젝트는 오늘 처음 활동한 순서로 빈 층 번호를 받는다(위층부터). 옥상(R)=대표실.
- 층을 클릭하면 오른쪽 메인 씬이 그 층의 사무실로 바뀐다(엘리베이터 이동 애니 0.4초). 한 층에 세션이 여러 개면 층 안의 **방 탭**으로 유지(sid 앞 4자, 가장 최근 활동 방 기본).
- 건물 꼭대기 전광판: 시계(로컬), 오늘 총 위임 수, 규칙 준수 %.
- 전체 보기(건물 아이콘 클릭): 모든 층을 작은 단면으로 한 번에 — 각 층에 점(캐릭터)만 움직임.

## 2. 직급·이름 (사용자 = 대표)
- **대표(CEO) = 사용자.** `UserPromptSubmit` 때 대표 캐릭터가 대표실(옥상 R)에서 엘리베이터로 내려와 실장 책상에 지시서를 놓고 돌아간다. `PermissionRequest` 땐 실장이 결재판을 들고 대표실로 올라가 문 앞에 선다(승인 대기). `Stop` 이면 실장이 "보고 드렸습니다" 말풍선.
- 직급은 **모델**로: fable=실장, opus=책임, sonnet=주임, haiku=인턴, unknown=계약직.
- 직무는 **에이전트 타입**으로: backend-dev/implementer=개발, code-reviewer/reviewer=심사(QA), aws-ops/ops-investigator=운영, lookup/Explore=조사(사서), web-fetch=외근, Plan=기획, general-purpose=총무(만능), claude-code-guide=사내강사, 그 외=사원.
- 이름은 aid 해시로 고른 **동물 별명**(수달·여우·너구리·펭귄·고슴도치·두더지·햄스터·알파카·카피바라·올빼미·판다·토끼·고양이·강아지·다람쥐·코알라). 표기: `책임 개발 여우`, `인턴 조사 수달`, `실장 Fable` 은 고정 이름 "Fable 실장". 같은 별명 충돌 시 숫자 붙임.
- 명패(name tag)는 픽셀 폰트, 모델 색 띠(목걸이 사원증) + effort 막대. 호버/클릭하면 카드: 직급·직무·모델·effort·현재 일·경과·오늘 처리 건수·판정 기록.

## 3. 캐릭터 (16×24 픽셀 스프라이트, 3배 확대, 코드로 그림. 이미지 파일 금지)
| 직무/직급 | 특징(한눈에) | 일할 때 소품 |
|---|---|---|
| 대표(사용자) | 남색 정장·넥타이, 커피잔, 살짝 큰 키 | 지시서 봉투 |
| 실장 Fable | 보라 조끼, 안경, 클립보드, 왕관 대신 보라 머리띠 | 결재판·확성기(위임 시) |
| 책임 개발(opus) | 후드티, 노트북, 헤드폰 목에 | 타이핑 노트북, 키보드 불빛 |
| 주임(sonnet) | 셔츠+팔토시, 수첩 | 수첩에 메모 |
| 인턴 조사(haiku) | 베레모, 책 더미 안고, 뛰어다님(걸음 빠름) | 책 펼침, 돋보기 |
| 심사 QA | 빨간 펜, 큰 돋보기, 체크리스트 | 빨간 도장(OK/REWORK) |
| 운영 | 헤드셋, 공구벨트, 케이블 | 서버랙 LED 조작 |
| 외근 | 모자, 가방, 우산 | 문 밖으로 나갔다 들어옴 |
| 기획 | 안경, 포스트잇, 화이트보드 마커 | 화이트보드에 그림 |
- 모델 색은 사원증 띠·명패 테두리에만. 머리카락/옷은 직무별 고정이라 "뭘 하는 사람인지" 먼저 읽힌다.
- 상태 표현: 생각=머리 위 구름, 읽기=책 펼침, 명령=서버 LED, 쓰기=타이핑 스파크, 막힘=땀방울, 실패=번개+앉아서 머리 긁기, 승인 대기=손 들고 결재판, 퇴장=엘리베이터 + 도장.

## 4. 픽셀아트 비주얼
- 전체: 2px 픽셀 그리드, `image-rendering: pixelated`, 타일 기반 바닥(나무/카펫/타일), 창문에 시간대별 하늘(아침·낮·저녁·밤, 로컬 시간). 패널·카드·버튼도 픽셀 테두리(3px 계단 모서리) + 하드 섀도우.
- 픽셀 폰트: 한글 지원 OFL 픽셀 폰트가 시스템에 있으면 사용(`local("Galmuri11")`, `local("NeoDunggeunmo")`, `local("DungGeunMo")`), 없으면 시스템 고딕. 네트워크 로드 금지. README 에 폰트 설치 안내.
- 방 이름(친근하게): 도서관(자료실), 개발실(작업대), 서버룸, 회의실, QA실(검수실), 외근·민원실(외부창구), 탕비실(idle 커피), 대표실(옥상), 엘리베이터. 방 이름 옆에 작은 픽셀 아이콘.
- 애니: 걷기 4프레임, 타이핑 2프레임, 책장 넘김 2프레임, 엘리베이터 문, 도장 쾅(스케일 바운스). 모두 CSS steps() 또는 rAF 스프라이트 프레임. prefers-reduced-motion 존중.
- 색: 파스텔 기반 16색 팔레트 하나로 통일(라이트/다크 2세트). 모델 색 4개는 그대로(fable 보라, opus 남색, sonnet 청록, haiku 호박).

## 5. 사용량 (Claude 토큰) — 데이터와 그래프
### 데이터 (서버 `usage.mjs`)
- 소스: `~/.claude/projects/<proj-dir>/*.jsonl` 과 `<proj-dir>/<sid>/subagents/agent-*.jsonl`. 오늘(로컬) mtime 파일만 tail. `type=="assistant"` 레코드의 `message.model`, `message.usage{input_tokens,output_tokens,cache_read_input_tokens,cache_creation_input_tokens}`, `timestamp`. 같은 message id 가 여러 줄(스트리밍)이면 마지막 값만.
- 프로젝트: 디렉터리명에서 복원(`-Users-x-Documents-AI_Team` → `AI_Team`, 마지막 세그먼트). 세션: 파일명(sid). 에이전트: `subagents/agent-<aid>.jsonl` 의 aid (meta.json 에 타입이 있으면 함께).
- 모델 패밀리: 이름에 fable/opus/sonnet/haiku 포함 여부로 분류.
- SSE: `event: usage` 로 `{ts, proj, sid, aid?, model, family, in, out, cacheR, cacheW}` 레코드 스트림 + 시작 시 오늘치 배치. 클라이언트가 집계.
- 비용: 단가를 추측하지 않는다. `~/.claude/ai-team-office/pricing.json`(사용자가 적는 USD/1M 토큰 표)이 있을 때만 금액 표시, 없으면 토큰만.
- 한계 표기: 요금제 5시간 창 한도·잔여량은 로컬에 없음 → 표시하지 않는다(README).

### 그래프 (프런트 `charts.js`, 외부 라이브러리 없음, SVG)
1. **모델별 사용 비율 도넛**: 오늘 출력 토큰 기준 fable/opus/sonnet/haiku 점유율. 가운데에 "Fable 절약률" = 1 − fable 출력 토큰/전체 출력 토큰.
2. **시간대별 스택 막대**: 오늘 0~23시, 모델별 스택(출력 토큰). 지금 시각 표시선.
3. **층(프로젝트)별 가로 막대**: 프로젝트별 총 토큰, 모델 색 분할.
4. **캐시 적중 게이지**: cache_read / (input + cache_read + cache_creation).
5. **입력 vs 출력 비율 바**, 세션 수·메시지 수 소형 숫자.
6. 메인(Fable) 직접 호출 토큰 vs 서브에이전트 토큰 비교 바 — 분배 규칙이 실제 토큰에서 지켜지는지.
- 모든 그래프에 툴팁(hover 값), 빈 상태 문구, 다크/라이트 팔레트, 픽셀 스타일 테두리. 차트 색은 모델 색 4개 + 중립 회색만.

## 추가 결정 (2026-10-21, 사용자 피드백)
- **층 설정 편집기**: 건물의 톱니 아이콘 → "층 설정" 모달. 서버 `GET /projects.json`(~/.claude/projects 스캔: proj·lastActive·sessionsToday)로 미배정 프로젝트 목록을 받고, 드래그로 층에 배치·층 순서 변경·라벨 인라인 편집. 저장은 `POST /building.json`(같은 출처·localhost 만, 엄격 검증, 원자적 쓰기, 이 파일 외 쓰기 금지). 마우스 휠로 층 이동, 엘리베이터 카 드래그로 층 이동.
- **비주얼 레퍼런스 = 복셀(Minecraft 풍)**: 블록 타일 바닥·벽(판자·조약돌·유리·옥상 잔디), 횃불 조명, 아이템 프레임 명패, 핫바 탭, 하트/경험치바 게이지, 각진 블록 캐릭터. 원작 텍스처·폰트·스킨·로고·명칭은 쓰지 않는다(공개 배포 저작권). 코드·UI 용어는 "voxel".
- **대표실(CEO room)**: 층과 무관하게 씬 우하단 고정 코너(유리 사무실, 포털 문). 사람 응답이 필요하면 누구든(메인·서브, 어느 층이든) 포털로 와서 대표 책상 앞에 줄을 선다. 트리거: AskUserQuestion(질문 본문=`ask`)·PermissionRequest(`ask`)·Notification permission(`msg`) = HIGH(벨·차임), Stop = LOW("보고 드렸어요", 문 앞 대기), Notification idle = LOW("입력을 기다리고 있어요", 배지 "대기 중"; 열린 보고가 있으면 덮지 않음, v0.2.3–0.2.4). 해소: 같은 캐릭터의 다음 도구 이벤트·해당 세션 UserPromptSubmit·SubagentStop. 카드: 직급 직무 별명·층·세션·대기 시간·질문 전문·"복사"·"터미널로"(`GET /focus?sid=` 가 iTerm2/Terminal 의 해당 tty 탭을 활성화, 입력은 절대 하지 않음). 브라우저에서 답을 세션에 넣는 기능은 Claude Code 에 외부 입력 통로가 없어 제공하지 않는다(README 명시). 훅에 `ask`·`tty` 필드 추가(2026-10-21).
- **보고 본문·빈 상태·대표 의자 (v8)**: Stop/SubagentStop 이면 훅이 `msg`(공식 문서상 Stop·SubagentStop 입력의 `last_assistant_message`, 트랜스크립트는 늦을 수 있어 읽지 않음)를 4000자까지, 다른 이벤트는 300자까지 남긴다. 대표실 보고 카드와 캐릭터 카드("마지막 보고")에 줄바꿈 유지·가벼운 마크다운 정리(``` 줄·머리 # 제거, 글머리 •)로 보여 주고, 높이 240px 에서 자체 스크롤, "전체 복사". 항상 esc() 로 이스케이프, `--redact` 면 서버가 `msg` 를 빼서 본문 없음. "대표님께 온 요청이 없어요" 문구는 없앤다(대기 수는 헤더 "대기 N"). 대표는 한 캔버스에 그린 임원용 가죽 의자(등받이 뒤·팔걸이 앞, 크롬 다리·바퀴)에 앉고, 측면 책상이 무릎 바로 앞에서 시작해 손이 노트북 위에 놓인다(`ceo.js CEO_PLAN`, `sprites.js EXEC`).
- **중계가 붙잡는 조건 (v0.2.4)**: 권한 요청(`PermissionRequest`)은 대시보드 탭이 하나라도 열려 있으면(백그라운드 포함) 붙잡는다. 터미널 승인 창이 훅과 동시에 떠서 터미널에서 먼저 답할 수 있다는 전제(공식 문서 미명시, 실사용 관찰). 질문(`PreToolUse` AskUserQuestion)은 훅이 끝나야 터미널 질문 창이 뜨므로 **보이는** 탭이 있을 때만 붙잡는다. 마지막 보이는 탭이 숨으면 질문만 풀고, 탭이 닫히면 5초 유예 뒤 그때 연결된 탭 기준으로 판단한다(새로고침은 풀지 않음). 넘긴 요청은 서버 로그 `not relayed: <이유>`. 서버는 프로세스마다 `boot` id 를 `index.html` meta 와 `ready` 에 실어, 재시작을 넘긴 페이지는 새로고침해 새 토큰을 받는다(`ceocard.js staleBoot`).
- **대표실 답변도 이벤트 (v0.2.6)**: 서버가 `ceo-decisions.jsonl` 도 tail 해서 대시보드 답변(by dashboard)을 `RelayDecided {sid, aid, tool, answer}` 이벤트로 히스토리에 넣는다. 새로고침·재시작 뒤 리플레이에서도 승인된(아직 실행 중인) 요청이 버튼 없는 카드로 되살아나지 않는다. 터미널에서 승인한 긴 명령은 이런 이벤트가 없어 `PostToolUse` 까지 카드가 남는다(한계).
- **대표 책상 서랍 = 측면 (v0.2.7)**: 대표는 책상 오른쪽에 앉아 왼쪽(문)을 보므로 서랍장은 옆면(민짜 측판)이 문/관람자 쪽에 보이고, 서랍 앞면은 대표 쪽을 향해 오른쪽 모서리에 이음선과 손잡이 끝만 보인다(`style.css .ceo-desk .dped`).
- **노크 (v0.2.7)**: 대표실 줄에 새로 온 사람은 문(`CEO_PLAN.door`, 실제 문 x) 앞에 멈춰 손을 들고 "똑똑" 말풍선(시스템 글꼴, 약 0.8초)·1px 두드림 뒤 자기 자리로 걸어간다(`ceo.js ceoEntry`/`CEO_KNOCK`). 도착 1회만: 새로고침·히스토리 리플레이로 이미 기다리던 사람은 애니메이션 없이 제자리, +N 에 있다 자리로 들어오는 사람은 노크하지 않는다. 동시에 둘이 오면 둘째는 한 칸 뒤에서 노크. reduced-motion 이면 노크·말풍선 모두 생략. 소리 토글이 켜져 있으면 짧은 나무 두드림 두 번(WebAudio 합성).
- **호버 카드 유지 (v0.2.7)**: 마우스(넓은 화면)로 캐릭터나 대표실 대기자를 호버해 연 카드는 포인터가 캐릭터나 카드 위에 있는 동안 유지되고, 둘 다 벗어난 뒤 300ms 유예가 지나야 닫힌다(`ceo.js HoverHold`). 카드 안을 누르면 고정되어 승인·거절이 첫 클릭에 동작하고 거절 사유 입력 중에도 닫히지 않는다. 클릭 고정·바깥 클릭 닫기는 그대로, 터치·좁은 화면은 이전 동작 그대로.
- **결정을 묻는 보고는 남는다 (추정)**: 메인 `Stop` 보고의 끝 5줄(비어 있지 않은 줄, 글머리·`**` 제거, ``` 코드 블록 안 줄은 제외) 중 하나가 `?`/`？` 로 끝나거나(URL 은 지우고 판단) "할까요·될까요·정해 주세요·알려 주세요·결정해 주세요·승인해 주셔야/주시면…" 을 쓰거나(“확인해 주세요” 는 제외: 보통 "브라우저에서 확인" 안내) `다음 결정` 으로 시작하면(단 값이 없음·해당 없음·none·N/A·`-` 로 **시작**하면 제외, 뒤에 무엇이 와도 같음. 요청 문구가 같이 있으면 묻는 것으로 봄) `asks: true`, 말풍선 "결정을 기다려요", 카드 배지 "결정 대기" + **추정** 태그(문구로 추정, 관측 아님). 우선순위는 LOW 그대로(벨·차임 없음). 일반 보고는 90초 뒤 사라지지만 이 보고는 같은 캐릭터의 다음 도구 이벤트·그 세션 `UserPromptSubmit`·`SessionEnd` 까지 줄에 선다. 잊힌 세션이 하루 종일 서 있지 않도록 3시간(`ASK_MAX_MS`)이 지나면 다른 LOW 처럼 나간다(`ceo.js reportAsks`/`reportDecision`, `ceoExpire`). 본문이 없으면(`--redact`) 묻지 않는 것으로 본다. 한계: 문구 휴리스틱이라 놓치거나 잘못 잡을 수 있다.
- **크게 보기 = 카드 전체를 오른쪽 서랍으로**: 모든 카드(대표실 보고·승인·질문·알림·대기, 캐릭터 카드)의 아래 버튼 줄(돌려보내기 옆)에 "크게 보기". 보고 머리의 크게 보기는 없앴다. 서랍(`#reader`, role=dialog, 씬은 왼쪽에 그대로)은 위에서부터 ① 카드 머리(이름·배지·추정/결정 대기)와 메타(층·세션·기다린 시간) ② 큰 읽기 영역(결정 줄 강조 상자·목록·링크, A−/A+ 12–22px `localStorage office.readerSize`) ③ 카드 자기 동작(승인/거부+사유, 질문 답, 복사, 전체 복사, 돌려보내기, 터미널로). 작은 카드와 서랍은 같은 마크업(`app.js cardParts`)과 같은 처리기(`cardClick` → `onRelayClick`/`sendBack`)를 쓰므로 중계 규칙은 그대로다. 본문이 없는 카드는 읽기 영역에 내용을 보인다: 승인 = 도구·명령(또는 대상)·설명, 질문 = 질문·선택지 설명, 그 밖 = 요청 문구와 안내. 읽기 영역은 DOM(textContent)으로만 그리고 http/https URL 만 링크(`target=_blank rel="noopener noreferrer"`, `ceo.js linkParts`). 연 순간의 세션 id·대기 시점(since)·부제를 기억해, 같은 세션의 같은 대기(`ceo.js readerSame`)면 실시간으로 따라가고, 줄에서 나가거나(답·새 지시·돌려보내기) 캐릭터 키가 다른 세션 것이 되거나(층·방 전환) 사라지면 마지막 내용으로 얼리고 "지난 보고/지난 요청" 을 붙이며 동작은 전체 복사만 남긴다. 터미널로는 늘 연 세션으로 간다. 사유 입력 중에는 동작 영역을 다시 그리지 않는다. 닫기·Esc·바깥 클릭(서랍만 닫고 카드는 남김), 열면 닫기 버튼에 포커스, Tab 은 서랍 안을 돌고, 닫으면 연 버튼 → 대표실 대기자 → 대표 → 대표실 머리 순으로 남은 곳에 포커스. reduced-motion 이면 슬라이드 없음, 760px 이하 전체 폭.
- **대표실 목록 (서랍 목록 모드)**: 대표(이제 버튼)나 +N 을 누르면 같은 서랍이 목록으로 열린다. 제목 "대표실 대기 N". 표: 선택 체크 | 온 시각(HH:MM:SS) | 기다린 시간 | 종류(승인·질문·결정(추정)·보고·대기, 색 점) | 프로젝트(층) | 누가 | 내용(한 줄, 말줄임: 질문 첫 줄, 묻는 보고는 결정 줄, 보고는 첫 줄). 기본 정렬은 온 시각 오래된 순, 머리를 누르면 그 열 오름/내림 토글(▲▼, `aria-sort`). 필터 칩 "답 필요만"(HIGH + 묻는 보고)/"전체"(기본). 정렬·필터는 `ceo.js ceoTable`/`nextSort`. 실시간 갱신은 스크롤 위치와 포커스한 행을 지키고, 목록을 연 뒤 새로 온 요청은 끼워 넣지 않고 "새 요청 N건 · 보기" 막대로 알린다(보이는 행이 하나도 없으면 바로 보임). 행 클릭/Enter = 그 카드 전체 보기 + "← 목록"(스크롤 복원), 행은 Tab·↑↓ 로 이동, Space = 선택. 빈 상태 "대기 중인 요청이 없어요". 하위 에이전트 묶음(×N)은 미정이라 없음.
- **목록 다중 선택·일괄 돌려보내기**: 행 체크 + 머리 체크(지금 필터로 보이는 행 전체; 필터 밖 선택은 유지), Shift+클릭 = 범위. 선택이 있으면 "N건 선택 · 돌려보내기 · 선택 해제" 막대. 돌려보내기는 카드 하나의 돌려보내기와 같은 `sendBack`(중계 항목은 `POST /relay/release` = 결정 없이 풀기, 그리고 `DismissStore`/`dismissKey` 로 이번 대기만 숨김)이며 승인·거부·답을 절대 보내지 않는다. 선택에 승인·질문(HIGH)이 있으면 한 줄 확인 "승인·질문 N건은 터미널에서 여전히 기다려요. 돌려보낼까요?". 선택은 실시간 갱신·정렬·필터 변경을 넘어 살아 있고, 해소된 행은 선택에서 빠진다(`ceo.js pruneSel`/`selectRows`/`selectRange`/`selState`/`selHigh`).
- **+N 버튼**: 대표실 줄이 넘치면 마지막 사람과 몇 칸(3 world units) 떨어져 문 쪽에 34×32px 이상 버튼 "+N"(호버 시 보라, 포인터 커서). 자리가 모자라면 줄에 서는 사람을 하나 줄인다(최소 1명, `ceo.js ceoMore`). 누르면 목록.
- **디버그 URL**: `?read=1` 첫 보고(결정 대기 우선) 카드를 서랍으로, `?list=1` 목록을 바로 연다. 시뮬레이터(`sim.js`)는 결정 대기 긴 보고·승인 2건(메인 Bash, 하위 에이전트 WebFetch)·질문·짧은 보고·대기를 내서 픽스처와 합쳐 7명이 줄을 서고 +N 이 보인다.
- **대시보드에서 지시 보내기 (Stop 중계, 선택 설치)**: 결정·질문으로 끝난 보고(`reportAsks`)에 대시보드에서 다음 지시를 보낸다. 구조: 선택 설치 훅 `office/hooks/ceo-stop.sh`(설정 스킬 (a2), `hooks.Stop`, 동기, `timeout` 330초 > 최대 대기 320초+5)가 Stop 입력을 `POST /relay/ask` 로 넘기고 기다린다. 대시보드가 답하면 훅이 **직접** `{"decision":"block","reason":"<글>"}` 을 만들어 출력한다(Claude Code Stop 훅 규약: 멈추지 말고 reason 을 받아 이어서 일함. 세션에는 Stop 훅 피드백으로 들어가며 UserPromptSubmit 은 생기지 않는다). 그 밖의 모든 경우(대시보드 꺼짐 ~1초, 보이는 대시보드 없음, 보고가 묻지 않음, 하위 에이전트, `OFFICE_RELAY_DISABLE=1`, 시간 초과, 돌려보내기·"터미널에서 할게요", 오류)는 아무것도 출력하지 않고 exit 0 → 평소처럼 멈춘다. 규칙:
  - 붙잡는 조건(모두): 메인 세션(`agent_id` 없음), `hook_event_name` Stop, `last_assistant_message` 가 묻는 보고(서버가 `public/ceo.js reportAsks` 를 그대로 import, 구현은 하나), **보이는** 대시보드 탭이 있음(질문과 같은 규칙: Stop 훅이 도는 동안 터미널은 그 세션의 입력을 받지 못하므로 백그라운드 탭만으로는 붙잡지 않음). `stop_hook_active=true`(지시로 이어진 뒤의 Stop)도 붙잡을 수 있다 — 이어짐마다 사람이 답하므로 무한 반복이 아니다. 마지막 보이는 탭이 숨거나 닫히면 질문과 같이 풀린다.
  - 대기: `OFFICE_RELAY_STOP_WAIT_MS` 기본 120000, 100..320000 로 자름(스크립트와 서버 `STOP_WAIT_MAX` 모두; curl 대기+5초 < 훅 timeout 330초). 기다리는 동안 터미널에는 Stop 훅이 실행 중으로 보인다(README).
  - 연속 지시 상한: 세션마다 대시보드 지시 8번(`INSTRUCT_CAP`, Claude Code 의 Stop 연속 8번 상한과 맞춤). 넘으면 붙잡지 않고 `ended{reason:'cap'}` → 카드 "연속 지시는 8번까지예요 · 터미널에서 이어 주세요". 그 세션 `UserPromptSubmit`/`SessionEnd` 에 0 으로.
  - 호출 프로세스 확인이 안 되는 곳(macOS 아님): 지시를 붙잡지 않고(`unchecked`), 지시 답은 403, 카드가 그렇게 말한다. `OFFICE_TEST_ANCESTRY`(가짜 프로세스 트리)는 `node --test` 아래(`NODE_TEST_CONTEXT`)에서만 따르고 실제 실행에서는 무시·로그.
  - 서버: 새 중계 종류 `instruct`(item.tool = `Stop`). 같은 `/relay/ask`·`/relay/answer`·`/relay/release` 와 기존 보호(127.0.0.1, Host/Origin, 같은 출처 + 뷰어 토큰, Claude Code 프로세스 트리 호출 거부, 지난 항목 409/404/410)를 그대로 탄다. 답 `{text}` 만 허용: 문자열, `\r\n`→`\n`, `\n` 외 제어문자→공백, 앞뒤 공백 제거, 1..2000자(넘거나 비면 400). 결정 로그(`ceo-decisions.jsonl`)에 남고 `RelayDecided` 로 리플레이된다(`--redact` 면 글 대신 `{instructed:true}`). 해소: 그 세션 `UserPromptSubmit`/`SessionEnd`(같은 Stop 의 office-events 줄로는 해소하지 않음). item 에는 표시용 보고 본문(`msg`, 4000자, `--redact` 면 없음)을 싣는다.
  - 훅 출력: 응답의 `.kind == "instruct"` 이고 `.decision.text` 가 문자열일 때만, 훅이 jq 로 같은 정리(제어문자·2000자)를 다시 하고 비어 있지 않을 때만 `{"decision":"block","reason":…}` 을 출력한다. 서버가 다른 필드를 넣게 만들 수 없다.
  - UI: 결정(추정) 보고 카드와 그 서랍에 instruct 항목이 붙어 있으면 입력칸(Enter = 줄바꿈, Ctrl/⌘+Enter = 보내기, 2000자), 빠른 칩("진행해 주세요"·"머지해 주세요"·"보류해 주세요", 누르면 칸을 채움), 보내기, "터미널에서 할게요"(= 돌려보내기, 결정 없음), 남은 시간 ⏱, 안내 "보낸 글은 대표님이 친 지시처럼 세션에 전달돼요". 승인·거부와 같은 중복 전송·`data-rid` 보호. instruct 항목이 없으면(훅 미설치·시간 초과·넘김) 가짜 입력칸 없이 흐린 한 줄: 이 페이지에서 instruct 항목을 한 번도 못 봤으면 "대시보드 지시는 설치 후 쓸 수 있어요 · 터미널로", 봤으면 "이 보고는 대시보드 지시 시간이 지났어요 · 터미널로". 우선순위는 LOW 그대로(벨 없음).
- **버튼 없는 카드는 이유를 말한다**: 대시보드에서 답할 수 없는 승인·질문 카드는 막연한 안내 대신 아는 만큼 구체적으로 적는다(`ceocard.js whyNoButtons`): 시간 초과 = "<실제 대기> 동안 대시보드 답을 기다리다 터미널로 넘겼어요", 붙잡지 않음 = "대시보드가 열려 있지 않아 터미널로 갔어요"/"대시보드 탭이 뒤에 있어 터미널로 갔어요", 훅이 끝남 = "터미널에서 먼저 답했거나 훅이 끝났어요", 서버 시작 뒤 그 세션의 중계 요청을 한 번도 못 봤으면 "대표실 중계가 설치되지 않았어요"(추정 태그), 그보다 오래된 요청은 "지난 요청이거나 서버가 다시 시작됨". 근거: 서버가 결정 없이 끝난 요청(timeout·no-viewer·hidden·withdrawn)을 기억해 `event: ceo` `{type:'ended'}` 로 알리고 `snapshot.ends`(오늘치)·`startedAt` 에 싣는다(새로고침에도 유지). 결정 로그 줄에 `wait` 를 남겨 재시작 뒤에도 오늘치 끝남을 다시 읽는다. 시간 초과는 서버 로그에 `대표실: <tool> (<sid8>) expired after <s>s` 로 남는다.
- **호버 카드 전환은 머물러야 (v0.2.8+)**: 마우스로 연 카드가 열려 있을 때 다른 사람으로 바꾸려면 그 사람 위에 약 150ms 머물러야 한다. 카드로 가는 길에 다른 사람을 지나치는 것만으로는 바뀌지 않고, 포인터가 카드 위에 있는 동안에는(카드가 사람과 겹친 자리라도) 아래 사람이 끼어들지 못한다(`ceo.js HoverHold.over/out`, 첫 호버는 바로 열림, 300ms 닫힘 유예는 그대로). 터치·좁은 화면은 이전 그대로.
- **대표실 묶음 (넘칠 때만)**: 줄이 방에 다 들어가면 지금처럼 한 사람씩 선다. 넘칠 때만 세션별로 묶어 세션당 한 사람이 선다: 그 세션에서 가장 급한 사람(HIGH 먼저, 그다음 가장 오래 기다린 사람; 실장이 아닐 수 있음), 머리 위 "×N" 배지(안에 HIGH 가 있으면 빨강), 툴팁 "세션 d8e9 · 실장 결정(추정) · 질문 1 · 승인 1". 줄 순서는 묶음 안에서 가장 오래 기다린 시각 순. 묶음을 누르거나 Enter = 그 세션만 걸러진 목록 서랍(필터 칩 "2F 쇼핑 OMS · 세션 d8e9 · 3건", ✕ 로 해제), 1건짜리는 바로 그 카드. +N 은 남은 묶음 수, 머리 "대기 N" 은 여전히 건수. 이미 기다리던 사람이 묶이거나 기존 묶음에 새로 합류하면 다시 걸어 들어오거나 노크하지 않고 배지가 한 번 커졌다 돌아온다(reduced-motion 이면 없음). `ceo.js ceoGroupPlan`/`groupTip`/`groupEntry`, `ceoTable({sid})`. 시뮬레이터는 기본으로 넘친다(9건, 2층 세션이 ×3).
- **대기 기본 2분, "터미널에서 답할게요" (0.2.8 이후)**: 승인·질문·지시 중계의 기본 대기는 120000(2분, 지시 최대 320000). 대시보드는 주로 지켜보는 곳이고 답은 보조다. 열린 중계 카드(승인·질문·지시, 작은 카드와 서랍)에 "터미널에서 답할게요"(지시는 "터미널에서 할게요", 파란 테두리 `chipbtn term`)가 있다: `/relay/release` 로 지금 결정 없이 풀어 터미널 프롬프트가 바로 뜨고, 카드는 남아 "터미널로 넘겼어요 · 터미널에서 답해 주세요" 를 보이며 키보드 포커스는 "터미널로" 로 간다. "돌려보내기"(회색 테두리)는 같은 풀기에 대시보드에서 숨기기까지 한다. 같은 `data-rid`·중복 전송 보호.
- **전체 보기에서는 대표실 모서리를 숨긴다**: 전체 보기(모든 층 목록)에서 대표실 모서리가 그리드 위에 잘려 떠 있던 문제(0.2.8). 전체 보기 동안 `#ceo` 를 통째로 숨기고(카드·호버 영역 포함, 열린 대표실 카드는 닫음), 머리의 "대표님 호출" 은 목록 서랍을 연다.
- **묶음 전환은 제자리**: 줄이 넘쳐 묶이거나 풀릴 때, 이미 기다리던 사람은 절하고 나가거나 다시 걸어 들어오지 않고 제자리에서 바뀐다(`groupEntry`: 아는 사람이면 anim 없음; 떠나는 그림도 사람이 아직 줄에 있으면 절 없이 교체). 절은 실제로 줄을 떠난 사람만. 서랍을 닫을 때 포커스는 그 세션의 묶음 그림으로도 돌아간다.
